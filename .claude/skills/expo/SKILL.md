# Expo

This project targets **Expo SDK 57** with **expo-router** (file-based routing),
managed workflow, **pnpm** with `node-linker=hoisted`, and TypeScript strict.

## Official Expo skills are not vendored here

Expo publishes 24 agent skills at
[expo/skills](https://github.com/expo/skills) (MIT). They are **installed**, not
copied into the repo, because Expo revises them each SDK release — a vendored
copy would silently rot and start giving SDK-55-era advice on an SDK-57 project.

Install them once, locally:

```sh
# Claude Code
claude plugin install expo@claude-plugins-official

# Codex
codex plugin add expo@openai-curated

# Cursor and other agents
npx skills add expo/skills
```

What they cover:

| Area      | Skills                                                                                                                                                                                                            |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework | `expo-overview`, `expo-project-structure`, `expo-router`, `expo-data-fetching`, `expo-design-system`, `expo-ui`, `expo-native-ui`, `expo-animation`, `expo-dev-client`, `expo-module`, `expo-dom`, `expo-upgrade` |
| Platform  | `expo-app-clip`, `expo-brownfield`, `expo-web-to-native`, `expo-tailwind-setup`, `expo-examples`                                                                                                                  |
| EAS       | `eas-app-stores`, `eas-hosting`, `eas-observe`, `eas-simulator`, `eas-update-insights`, `eas-workflows`                                                                                                           |

## Project conventions that override generic Expo advice

- **Adding dependencies:** use `pnpm exec expo install <pkg>`, never `pnpm add`
  directly, for anything with native code. Expo pins versions to the SDK, and
  `pnpm add` will happily install an incompatible one. Verify with
  `pnpm exec expo install --check`.
- **Running on device:** prefer a development build over Expo Go. Expo Go bundles
  a fixed set of native modules, so anything outside it fails at runtime.
- **No `android/` or `ios/` directories:** this is a managed project. They are
  generated by `expo prebuild` in CI and are gitignored. Configure native
  behaviour through `app.json` and config plugins, not by editing native files.
- **Path alias:** `@/*` maps to `./src/*` (see `tsconfig.json` and
  `babel.config.js`). Both must agree if the alias ever changes.
- **`babel.config.js` is security-sensitive.** It executes on every build. Keep
  it minimal, and never paste generated or minified content into it. CI fails the
  build if it grows past 4 KB or contains obfuscated code — see
  `scripts/forbidden-pattern-scan.sh`.

## Upgrading the SDK

```sh
pnpm add expo@latest
pnpm exec expo install --fix     # aligns every expo-* package and react-native
pnpm exec expo install --check   # verify
```

Then run the full gate before committing: `pnpm lint`, `pnpm typecheck`,
`pnpm exec tsc --noEmit --project tsconfig.test.json`, `pnpm test`,
`pnpm format:check`, `pnpm audit --audit-level high --prod`, `pnpm scan`.
